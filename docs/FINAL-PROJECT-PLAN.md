# แผนยกระดับเป็นระบบจำลองวงจรสำหรับโครงงานจบ (2026-11-23)

คำขอ: ยกระดับเว็บไซต์ให้นักเรียนออกแบบ ต่อวงจร เขียนโค้ด และทดสอบโครงงานจบได้ (ระยะที่ 1–6) — **ไม่เขียนระบบใหม่ทับ** ต่อยอดจากโครงสร้างเดิม และทดสอบว่าฟังก์ชันเดิมไม่เสีย

หลักที่ใช้ตลอด:
- ความถูกต้องทางอิเล็กทรอนิกส์และการนำไปสร้างจริงสำคัญกว่าความสวยงาม
- ห้ามใช้ภาพหรือแอนิเมชันที่ตั้งไว้ล่วงหน้าแทนผลของโค้ด: ทุกการตอบสนองต้องมาจากโค้ดที่คอมไพล์และรันบนตัวจำลอง ผ่านขาและบัสในวงจร
- ห้ามอ้างว่าจำลองฮาร์ดแวร์ได้ครบเมื่อยังไม่มีตัวจำลองชิปนั้น: UNO Q ใช้ **โหมดจำลองพฤติกรรม (behavioral)** ระบุชัดทุกจุดที่ผู้ใช้เห็น

## 2. แผนตามลำดับความสำคัญ

1. **(รอบนี้)** UNO Q behavioral + อุปกรณ์ใหม่ + กระแสเซอร์โว + ตรวจการต่อไฟ + แม่แบบเครื่องจ่ายยา + เทสต์รวม
2. **(ทำแล้ว 2026-11-25 — `docs/REPORT.md` หัวข้อ 85)** แม่แบบ 2 (รดน้ำต้นไม้) และ 5 (ควบคุมมอเตอร์) บน UNO Q — อุปกรณ์มีครบในคลังแล้ว
2b. **(ทำแล้ว รอบ 86 — เร็วขึ้น ≈ 2.8 เท่าบน Node, ผลเท่าเดิม)** ความเร็วตัวแก้สมการเมื่อ PWM ขับโหลดขดลวด (มอเตอร์) — ยังช้ากว่าเวลาจริง ≈ 15 เท่า ต่อไปต้องเป็นตัวแก้สมการแบบเมทริกซ์เบาบางทั้งชุด (REPORT 86.2)
3. แม่แบบ 3, 4, 6 — ส่วนเครือข่าย (Wi-Fi/Bridge) ไม่มีตัวจำลอง จะทำเฉพาะส่วนเซนเซอร์/ขับโหลด และระบุชัด
4. รูปวงจร (schematic) สร้างอัตโนมัติจาก netlist ของวงจรที่ผู้ใช้ต่อ, การจัดกลุ่มอุปกรณ์
5. UNO Q แบบเฟิร์มแวร์ (ถ้ามีตัวจำลอง Cortex-M33 + Zephyr ที่ใบอนุญาตใช้ได้) — ยังไม่มีในรอบนี้

## 3. ข้อจำกัดที่ประกาศ (UNO Q)

- รันสเก็ตช์บนตัวจำลอง ATmega328P: เวลาคำสั่ง (16 MHz) หน่วยความจำ (32 KB/2 KB) และ PWM (490/980 Hz) เป็นของ AVR ไม่ใช่ STM32U585
- ไม่รองรับ (คอมไพล์แล้วแจ้งข้อผิดพลาดภาษาไทย): Bridge/RPC, LED matrix, Wire1 (Qwiic), Wire2 (A4/A5), Serial1, analogReadResolution/analogWriteResolution, ไลบรารี Zephyr
- ฝั่ง Linux (QRB2210, Debian, App Lab Python) ไม่จำลอง
- โค้ดที่ผ่านในแอปต้องคอมไพล์ใหม่ด้วย Arduino App Lab/IDE (Zephyr core) และทดสอบทีละส่วนบนบอร์ดจริง
