# Audit ระบบ Circuit Lab 3D เทียบกับ Master Prompt (2026-10-29)

เอกสารนี้ตอบข้อ 15 ของ Master Prompt: ตรวจโค้ดและสถาปัตยกรรมปัจจุบัน แยกส่วนที่เป็นการจำลองจริงกับส่วนที่เป็นเพียงภาพ 3D ทำตารางความสามารถของบอร์ด ระบุข้อบกพร่อง และเสนอแผนเรียงตามความสำคัญ
ตารางความสามารถรายบอร์ดอยู่ในโค้ดที่ `src/model/board-features.ts` (แสดงในแผงคุณสมบัติของบอร์ด หัวข้อ "ความสามารถของบอร์ด") และถูกตรวจโดย `tests/board-features.test.ts`: ข้อที่เป็น Supported ต้องอ้างไฟล์เทสต์ที่รันโค้ดจริง

## 4. ข้อบกพร่องที่พบระหว่าง Audit และแก้แล้วในรอบนี้

1. **บริการคอมไพล์ Arduino แปลง `ISR(PCINT2_vect)` เป็น prototype ผิด** (`I SR(PCINT2_vect);`) ทำให้ sketch ที่ใช้ ISR คอมไพล์ไม่ผ่านทั้งที่ Arduino IDE ผ่าน → แก้ regex ใน `server/compile.mjs` (ชนิดคืนค่ากับชื่อต้องคั่นด้วยช่องว่าง/`*`/`&`) + เทสต์
2. **Uno: `SPI.transfer()` ค้างตลอดไป** (ไม่มีตัวจำลอง SPI ต่อไว้ บิต SPIF ไม่เคยขึ้น) → ต่อ `AVRSPI`: ส่งเสร็จตามเวลาสัญญาณนาฬิกา ไบต์ที่อ่าน = ระดับขา MISO จากวงจร (ระบุเป็น Partial)
3. **Uno: EEPROM ไม่ทำงาน** (`EEPROM.read` ได้ 0 เสมอ ค่าที่เขียนหาย) → ต่อ `AVREEPROM` ขนาด 1 KB คงอยู่ข้าม RESET/อัปโหลด/เริ่มจำลองใหม่ ตลอดการเปิดหน้าเว็บ (ยังไม่บันทึกลงไฟล์งาน — Partial)
4. **Uno: watchdog ไม่ทำงาน** (wdt_enable แล้วไม่รีเซ็ต) → ต่อ `AVRWatchdog` และเมื่อหมดเวลาทำการรีเซ็ตเต็มแบบปุ่ม RESET · หลังรีเซ็ต watchdog ปิดและ MCUSR = 0 เหมือนบอร์ดจริงที่ optiboot จัดการก่อนเข้าโปรแกรม
5. **Pico: `machine.WDT` หมดเวลา หรือ `machine.reset()` ทำให้ worker หน่วยความจำเต็มและล่ม** (rp2040js ไม่มีตัวรีเซ็ต ค่าเริ่มต้นเขียน log ซ้ำไม่รู้จบ) → หยุด CPU ทันที แล้วบูต MicroPython ใหม่จากแฟลชเดิมในคำขอถัดไป (main รันซ้ำเหมือน main.py)
6. **Pico ที่สร้างใหม่ระหว่างจำลอง (เช่น เปลี่ยนรูป bg.bin) เริ่มนาฬิกาที่ 0** → เริ่มที่เวลาวงจรปัจจุบัน
7. Uno: interrupt ภายนอก (INT0/INT1, pin change) ทำงานอยู่แล้วใน avr8js แต่เอกสารเดิมระบุว่า "ยังไม่ต่อวงจร" และไม่มีเทสต์ → เพิ่มเทสต์ยืนยันและแก้ข้อความ
