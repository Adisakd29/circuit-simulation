# แผนขยาย Circuit Lab 3D สำหรับเรียนไมโครคอนโทรลเลอร์ (ปวช./ปวส.)

เอกสารนี้ตอบคำขอ "ขยายแอปให้รองรับการเรียนและทดลองไมโครคอนโทรลเลอร์ตั้งแต่พื้นฐานถึงโครงงาน" — ตรวจสิ่งที่มีอยู่ กำหนดระดับการรองรับของอุปกรณ์ทุกชนิด และลำดับพัฒนา
หลักการ: **ไม่นับว่า "รองรับ" จนกว่าอุปกรณ์ทำงานร่วมกับวงจรและโค้ดจริงผ่านขา/บัสที่จำลอง และมีชุดทดสอบอัตโนมัติ** · อุปกรณ์ที่ยังเป็นแค่โมเดลหรือแผน ต้องแสดงเช่นนั้นในแอป

ปรับปรุงล่าสุด: 2026-10-26 — ชุด 5 รอบที่ 1 (Arduino Uno + บริการคอมไพล์, แลป 43) และชุด 2 รอบที่ 1 (LED RGB, แลป 44) — ดูหัวข้อ 8

## 2. บอร์ด — เลือกชุดแรกและแผนรุ่นอื่น

**ชุดแรก: Raspberry Pi Pico (RP2040, รุ่นไม่มี Wi-Fi) + MicroPython** — เหตุผล:
1. มีตัวจำลอง CPU ระดับคำสั่งที่ทำงานในเบราว์เซอร์อยู่แล้วและผ่านการทดสอบกับวงจรใน 17 แลป (ไม่ใช่การเดาผลจากข้อความโค้ด)
2. MicroPython คอมไพล์และรันบนบอร์ดเอง (เฟิร์มแวร์จริง) — ไม่ต้องมีเซิร์ฟเวอร์คอมไพล์ จึงทำงานได้บนหน้าเว็บสถิตเดิมและออฟไลน์
3. rp2040js มีอุปกรณ์ภายใน I²C/SPI/PIO ครบ → ต่อยอดไป LCD I²C, OLED, BMP280, MAX7219, WS2812B (ผ่าน PIO) ได้โดยไม่เปลี่ยนบอร์ด
4. ใบอนุญาต MIT ทั้ง rp2040js และ MicroPython

"ทำงานร่วมกับโค้ด" = ทดสอบแล้วว่าโค้ดบน Pico ที่จำลองควบคุม/อ่านอุปกรณ์นี้ผ่านขาจริงได้ (◐ = ต่อกับขาได้ทางไฟฟ้า แต่ยังไม่มีแลป/ชุดทดสอบร่วมกับโค้ด)

## 5. Wi-Fi / Bluetooth / MQTT — นโยบายการประกาศ

| ระดับ | ความหมาย | สถานะปัจจุบัน |
|---|---|---|
| ยังไม่รองรับ | ไม่มีปุ่ม/สถานะ "เชื่อมต่อ" ใด ๆ | **ทุกบอร์ดตอนนี้** (Pico ไม่มี Wi-Fi) |
| จำลองภายในแอป | เครือข่ายเสมือนในแอป (เช่น MQTT broker ในหน้าเว็บ) — ต้องติดป้าย "จำลอง" ทุกจุด | แผน (ชุด 6) |
| เชื่อมบริการจริง | ต่อ broker/HTTP จริงผ่านพร็อกซี — ต้องมีการยินยอมและแสดงปลายทาง | ยังไม่มีแผน |

ห้ามแสดง "เชื่อมต่อสำเร็จ" โดยไม่มีการทำงานตามระดับที่ประกาศ

## 8. ชุดแรกที่ทำแล้ว (Pico) — สรุป

- **ระบบรันโค้ด**: ปุ่ม "ตรวจโค้ด (Compile)" ส่งโค้ดให้ `compile()` ของ MicroPython บนบอร์ดที่จำลอง (คอมไพล์เป็น bytecode จริง ไม่รัน) · ข้อผิดพลาดทั้งตอนคอมไพล์และตอนรันอ่านจาก traceback ของเฟิร์มแวร์ → แถบแดงบอกบรรทัดและชนิดข้อผิดพลาด เลขบรรทัดสีแดง แถบไฮไลต์ในตัวแก้ไข แตะแล้วไปที่บรรทัด · Run / หยุด (Ctrl-C) / รีเซ็ตบอร์ด / หยุดเวลา (Pause) แยกกัน · Serial Monitor (UART0) · การคำนวณอยู่ใน Web Worker มีงบเวลาต่อรอบ — โค้ดวนไม่สิ้นสุดไม่ทำให้หน้าเว็บค้าง
- **ขอบเขตภาษา**: MicroPython v1.24.1 เท่านั้น (ไม่มี C/C++) — แสดงในแผงโค้ด
- **ขา Pico**: ป้ายขาแสดงหมายเลขขาจริง ชื่อ GPIO และหน้าที่พิเศษจากตาราง function select (ADC เฉพาะ GP26–28, PWM slice/ช่อง, I²C/SPI/UART) · ข้อจำกัดไฟฟ้า (3.3 V ไม่ทน 5 V, กระแสต่อขา) ในแผงคุณสมบัติ · ใช้ ADC กับขาที่ไม่มี ADC → ValueError จากเฟิร์มแวร์ชี้บรรทัด
- **ระดับการรองรับ**: ทุกอุปกรณ์ในคลังมีป้าย (จำลองครบ / จำลองบางส่วน / ยังไม่รองรับ) และในแผงคุณสมบัติมีรายละเอียด 6 ด้าน + ข้อจำกัด ก่อนเริ่มทดลอง
- **แลป 42**: VR → ADC → PWM หรี่ LED พร้อมแบบฝึกเปลี่ยนค่า (ความถี่ PWM) และภารกิจแก้ข้อผิดพลาด (ADC(15), ลืม `:`)
- รายละเอียดการทดสอบ: `docs/REPORT.md` หัวข้อ 54

### 8.18 ตัวถอดรหัส I²C + เวลาของบัส I²C + แลป 58 (2026-11-02)
- I²C ฮาร์ดแวร์ของ Uno/Nano (TWI) และ Pico (I2C0/1) **ใช้เวลาตามคาบ SCL ของชิป** (เดิมเสร็จทันที): START ½ คาบ, ที่อยู่/ไบต์ 9 คาบ, STOP 1 คาบ — Uno คาบ = (16 + 2·TWBR·prescaler)/16 MHz, Pico = (HCNT + LCNT)/clk_sys

- ไม่จำลอง: เวลาขึ้นของสายจากตัวต้านทานดึงขึ้น, clock stretching, การแย่งบัส (multi-master) · ยังไม่ถอดรหัส SPI
- รายละเอียด: `docs/REPORT.md` หัวข้อ 72

- STM32F103C8T6 "Blue Pill", Raspberry Pi Pico 2 (RP2350A) และ Teensy 4.1 (Teensy รุ่นไม่ได้ระบุในคำขอ — เลือก 4.1 ซึ่งเป็นรุ่นปัจจุบันของ PJRC) วางบนเบรดบอร์ด/โต๊ะได้ ตำแหน่ง/ชื่อขาตามแหล่งอ้างอิง โมเดล 3D ไม่มีโลโก้ · **ไม่มีการจำลอง CPU**: ขาไม่มีไฟ (มีเพียง GND/3V3 ของบอร์ดเดียวกันต่อถึงกัน), ไม่มีแท็บโค้ด, ทุกฟังก์ชัน Unsupported, แผงแสดงกล่อง "เฉพาะโมเดล — ยังรันโค้ดไม่ได้" และแจ้งเมื่อต่อสาย
- เงื่อนไขที่จะยกระดับเป็น "จำลองบางส่วน": มีตัวจำลอง CPU ที่ใบอนุญาตใช้ได้ + เฟิร์มแวร์ที่ build/ตรวจได้ + เทสต์รันโค้ดจริงผ่านขา (เช่น RP2350 ใน rp2040js ถ้ามีการรองรับ, STM32F103 ผ่าน QEMU/Renode บนเซิร์ฟเวอร์ — ยังไม่ได้ประเมิน)
- รายละเอียด: `docs/REPORT.md` หัวข้อ 84
